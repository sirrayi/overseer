## What changed from the 2026-09-29 plan

| 09-29 plan | Decision now | Why |
|---|---|---|
| SQLite FTS5 index | Pure-Rust BM25F index, built in memory, no persisted index | rusqlite adds 1–2 MB of static C to a 7 MB binary. At ≤20K small notes a hash-map index covers the whole corpus in milliseconds [infer]. A derived cache can be added later if a measurement shows it's needed. |
| `0.45·BM25 + 0.25·activation + …` | Reciprocal Rank Fusion over rank lists (k = 60) | BM25 is unbounded, activation is a log-odds and confidence is 0–1, so a raw weighted sum is not meaningful. RRF fuses heterogeneous rankers without normalisation [paper: Cormack et al. 2009]. No source supports the old weights. |
| Exponential recency | ACT-R power-law base-level activation | Forgetting is better fit by a power function than an exponential [paper: Wixted & Ebbesen 1991]. ACT-R derives it from use history [paper: Anderson et al. 2004]. |
| "Link activation" | One-hop `[[link]]` expansion with a fan penalty `S − ln(fan)` | ACT-R associative strength [paper: Anderson et al. 2004]. Personalised PageRank (HippoRAG) is overkill below ~20K nodes [infer]. |
| Dense embeddings (implied) | None | They need a local runtime of tens of MB plus a model download (fastembed/ort) [doc]. BM25 is a robust zero-shot baseline [paper: BEIR, Thakur et al. 2021]. Embedding-space triggers are also the attack surface AgentPoison exploits [paper: Chen et al. 2024]. |
| Per-note "importance" | Dropped | Frontmatter `confidence` already carries it [infer]. |

Kept from the 09-29 plan: a cross-project user store, a prospective layer, a sleep pass, poisoning defences, and a small resident budget. The LongMemEval-S eval is deferred until the owner lifts the benchmark hold.

## Evidence, by mechanism

**Activation: when is a memory needed?**
- ACT-R base-level learning is `B = ln Σ_j t_j^−d`, with the default `d = 0.5` holding "over a large range of applications". B estimates the log-odds that a memory is needed now [paper: Anderson et al. 2004, *Psych Review* 111].
- Storing the full use history is not required. Petrov's hybrid approximation keeps the k most recent uses exactly and folds the rest analytically, which preserves the recency spike [paper: Petrov 2006, ICCM].
- Spaced use slows forgetting and massed repetition barely helps [paper: Pavlik & Anderson 2005]. The log-sum already gives diminishing returns, so no extra term is needed [infer].

**Retrieval cues: encoding specificity**
- A trace is retrieved by cues that overlap its encoding context [paper: Tulving & Thomson 1973].
- So each note carries write-time `cues:` and is indexed on more than its body: name, cues, index line [infer].
- BM25F accumulates field-weighted term frequency before saturating: k1 = 1.2, b = 0.75 [paper: Robertson & Zaragoza 2009; Robertson, Zaragoza & Taylor 2004].
- Stemmers give no consistent gain for English [paper: Harman 1991, via Kraaij & Pohlmann 1996], so we use a minimal plural `s`-strip only.

**Fast episodes, slow facts: CLS and sleep**
- The hippocampus learns episodes fast, and the neocortex learns structure slowly through offline replay [paper: McClelland, McNaughton & O'Reilly 1995; Kumaran, Hassabis & McClelland 2016].
- Consolidation happens offline [paper: Diekelmann & Born 2010].
- Engineering mapping [infer]:
  - an episodic note is written per session, deterministically;
  - promotion to semantic facts happens in a batch pass on the small model;
  - nothing runs in the request path.
- Sleep-time compute: precomputing while idle cut test-time compute ~5× and added +13–18% accuracy on stateful tasks [paper: Lin et al. 2025, arXiv 2504.13171].

**Schemas and reconsolidation**
- New information joins an existing schema in one trial [paper: Tse et al. 2007, *Science*]. So consolidation prefers merging into an existing topic over creating orphan files.
- A retrieved memory becomes labile again [paper: Nader, Schafe & LeDoux 2000], but older memories resist [paper: Milekic & Alberini 2002].
- So a contradiction flags both notes for the sleep pass. A single contradiction never overwrites a settled, high-confidence note. v1's ADD-only `superseded_by` trailer already models this.

**Index, not store: hippocampal indexing**
- The hippocampus indexes cortical traces rather than holding their content [paper: Teyler & DiScenna 1986; Teyler & Rudy 2007].
- This is v1's `INDEX.md`. v2 keeps it and ranks its lines by activation within a fixed resident budget.

**Prospective memory**
- Intentions fire either by costly monitoring or by cheap cue-driven spontaneous retrieval, and focal cues trigger the cheap route [paper: McDaniel & Einstein 2000; Einstein et al. 2005].
- The harness does the "monitoring" with a deterministic cue scan, so the model pays nothing until a cue fires [infer].
- Prior art in agent harnesses is thin: Hermes cron, Letta schedules [unverified as memory mechanisms].

**Episodes and neighbours**
- Event boundaries gate encoding [paper: Zacks et al. 2007].
- EM-LLM retrieves temporally contiguous events alongside a hit [paper: Fountas et al. 2025, ICLR].
- Overseer already has boundaries (session, compaction, user input), so one episode note per session fits [infer].

**What agent-memory systems measured**
- Generative Agents score recency (0.995^hours), importance and relevance, all normalised to 0–1 and summed [paper: Park et al. 2023]. The sum only works because of the normalisation.
- Mem0 extracts facts, then chooses ADD/UPDATE/DELETE/NOOP [paper: Chhikara et al. 2025]. It reports ~26% over OpenAI's memory on LoCoMo [vendor].
- Zep adds bi-temporal edges [paper: Rasmussen et al. 2025]. v1 already has the flat-file analogue (`valid_from`/`valid_to`, `superseded_by`).
- A-MEM links Zettelkasten-style and retro-updates old notes [paper: Xu et al. 2025]. The retro-update is the part poisoning abuses, so v2 does not auto-rewrite old notes.
- Anthropic's memory tool is client-side file operations confined to a directory [doc]. Claude Code keeps a user/project split, with auto memory loaded up to 200 lines / 25 KB [doc].

**Benchmarks, for when the eval hold lifts**
- LongMemEval found:
  - round-level indexing beats session-level, which beats extracted facts;
  - fact-augmented keys beat flat indexing;
  - time-aware query expansion helps temporal questions [paper: Wu et al. 2024, ICLR 2025].
- LoCoMo is unreliable:
  - 6.4% of its answer key is wrong;
  - its judge accepts 62.8% of deliberately wrong answers;
  - Zep's 84% corrects to 58.44% [audit].

  Use LongMemEval-S with ≥3 runs.
- The ~95–96% LongMemEval-S ceiling and the ≤7% MemoryAgentBench conflict-resolution figure are [unverified].

**Poisoning**
- A query-only attacker can plant bridging records that hijack later queries [paper: MINJA, Dong et al. 2025].
- Five injected texts in a million-document corpus reach 90% attack success, and paraphrase, perplexity and dedup defences fell short [paper: PoisonedRAG, Zou et al. 2025].
- An indirect prompt injection wrote persistent exfiltration instructions into ChatGPT memory [doc: Rehberger, "SpAIware", 2024].
- The lesson: a memory write triggered by untrusted content must never be silent.
- Evidenced mitigations, strongest first:
  1. trust-tiered writes;
  2. a write quarantine;
  3. provenance tags;
  4. per-turn write caps.

  None fully solves retrieval poisoning [paper].

## Decisions

1. **Stores.**
   - A user store at `~/.overseer/memory/`, shared across projects.
   - A project store at `~/.overseer/projects/<slug>-<hash8>/memory/`, outside the workspace, so it never plants a nested git repo in the user's project.
   - `--memory` keeps v1's in-workspace `<cwd>/memory`.
   - `--no-memory` turns memory off. `--bare` always turns it off.
   - Memory is **on by default**: an assistant that forgets every session is not the product.
2. **Format.**
   - Markdown files with v1 frontmatter, plus optional `cues:`, `trigger:` and `fired:`.
   - `[[name]]` links in the body.
   - Layers: `profile/`, `episodic/`, `semantic/`, `procedural/`, plus the new `prospective/`.
   - Untrusted-origin writes land in v1's `proposals/` quarantine: never indexed, never recalled.
3. **Index.**
   - A BM25F index over fields name (boost 4), cues (3), index line (2) and body (1).
   - Built lazily in memory on first use, and refreshed by an mtime check.
   - No persisted index: `DEFERRED` behind a build-time measurement gate.
4. **Ranking.**
   - First, hard filters: the note is current, it is not in the quarantine, and sensitivity and governance pass for subagent views.
   - The candidates are the BM25F matches plus one-hop links of the top hits.
   - The final order is RRF(k = 60) over three rank lists: BM25F, activation `B`, and confidence.
5. **Activation.**
   - Petrov hybrid: `n`, first-use time and the last 3 use times per note; `d = 0.5`, t in days, floored at one hour.
   - A "use" means a note is written or its content is served (get, recall).
   - Uses are recorded in an append-only journal under `<store>/.index/`, which is gitignored and compacted by the sleep pass.
   - Never recorded in `events.jsonl` or in frontmatter.
6. **Resident segment.** User and project `CORE.md` (≤1,500 chars each) plus at most 24 index lines ranked by activation, under a hard cap of 4,000 chars (~1K tokens), frozen per session; everything else is reachable through `memory search` and recall. When both stores are empty it shrinks to one line.
7. **Recall.**
   - On each user input, the top ≤3 notes that clear a deterministic relevance bar are appended below the cache boundary as a bounded block.
   - The block is recorded in the event log so a resume rebuilds an identical view.
   - Engine-written episode notes are excluded from recall (still searchable).
8. **Prospective.**
   - `trigger:` takes `at:<rfc3339>`, `kw:<terms>` or `path:<glob>`.
   - Scanned deterministically once per user turn (at, kw) and on file-tool paths (path).
   - Fires once, then latched with `fired:`.
9. **Episodes and sleep.**
   - The engine writes one deterministic episode note per session at each run end. It is rewritten in place and carries engine provenance.
   - `overseer consolidate` keeps v1's index dedupe and adds episode→semantic distillation as ADD or supersede operations, which the engine validates.
10. **Security.**
    - An armed untrusted latch sends every memory write to the quarantine, with confidence ≤ 0.3.
    - At most 5 memory writes per turn.
    - Recalled text is provenance-wrapped.
    - Subagent views keep the v1 sensitivity and governance filter across both stores.

## Deferred
- A persisted index cache: owner engine; gate is a build time over 50 ms on a real store.
- A LongMemEval-S adapter and runs: owner eval; gate is the owner lifting the benchmark hold.
- Nightly consolidation from the gateway daemon: owner gateway; gate is memory v2 in use.
- `overseer memory purge` (hard delete plus history rewrite): owner CLI; gate is owner demand. Today, `forget` expires a note.
