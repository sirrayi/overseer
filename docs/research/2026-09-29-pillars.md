## 1. Caching and token economics

**What is true now**
- Anthropic [doc]:
  - A cache breakpoint writes and reads the `tools → system → messages` prefix, with max 4 breakpoints and a 20-block lookback.
  - A run of consecutive tool_use or tool_result blocks counts as one lookback position.
  - Minimum cacheable prefix: 1,024 tokens (Sonnet 5, Opus 4.8), 2,048 (Opus 4.7), 4,096 (Haiku 4.5, Opus 4.5/4.6). Below the minimum, the request is silently uncached.
  - The 5-minute TTL is refreshed free on a hit. Pricing: 1.25× write, 0.1× read. The 1h TTL costs 2× to write.
  - A top-level `cache_control` ("automatic caching") now exists and moves the breakpoint forward as the conversation grows.
- OpenAI [doc]:
  - Caching is automatic above 1,024 tokens, with hits rounded to 128.
  - `prompt_cache_key` matters for routing on models before GPT-5.6; on 5.6+ it only separates accounting.
  - Responses usage reports `input_tokens_details.cached_tokens` and `cache_write_tokens`.
  - GPT-5.6+ adds explicit `prompt_cache_breakpoint`, plus `prompt_cache_options`.
- DeepSeek [doc]: on-disk caching is on by default. It persists units at request boundaries and at detected common prefixes, and reports `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`. It is best-effort.
- opencode Zen [src]: caching is best-effort and pool-routed, with `x-opencode-session` as the sticky key. Overseer already sends that key.

**Overseer finding [local, verified in code]**
- Breakpoints sit only on the tools tail and the system tail (`provider/anthropic.rs:57-85`). No message breakpoint exists, so every turn re-bills the whole conversation at full input price. This is the single largest cost leak in the harness.
- DeepSeek cache fields are not parsed, so cost is overstated on deepseek via opencode.
- The system prompt is re-assembled from disk on every step (`agent.rs:668`). A mid-session memory edit changes the prefix and rewrites the cache.

**Shipped (`feat/overseer-refresh`)**
- Rolling block-level breakpoint on the last message.
- Parse DeepSeek and Responses cache-write usage.
- `prompt_cache_key`, sent only to `api.openai.com`.
- The static prefix is frozen per Agent.
- `CacheStats` as a per-run delta on `RunEnd`, surfaced as `NN% cached` on the run line and in the dashboard.
- A startup-token regression test.
- Hit rates have not been measured on live traffic yet. That is the next measurement.

## 2. Context management and startup tokens

**State of the art**
- Resident footprints [src]:

  | harness | resident tokens |
  |---|---|
  | pi | ~1.1K (550 prompt + ~590 for 4 tool schemas) |
  | Codex | ~8.5K |
  | OpenCode | ~6.9K |
  | Gemini CLI | 10–13K |
  | Claude Code | 27–33K |

- Claude Code now defers all MCP and rarely used tools behind ToolSearch by default [src].
- JetBrains, "The Complexity Trap" (arXiv 2508.21433) [src]: plain observation masking halves cost versus a raw agent and matches LLM summarization on SWE-bench Verified. Overseer's stale-tool-result clearing is exactly this.

**Overseer**
- About 2.1–2.5K tokens resident (an estimate), second only to pi.
- Compaction is deterministic and a view over the log, so there is no LLM call. That is better than Claude Code or Codex.

**Shipped**
- Advertise only usable tools: `computer`, `struct_search` and `diagnostics` are gated on availability, computed once per registry.
- Tool descriptions are trimmed.
- Regression tests pin the sizes. Measured:
  - static prompt: 929 chars (~266 tokens)
  - resident tool specs with every optional tool forced on: 9,886 chars (~2.5K tokens), of which `computer` is 1,828 and is advertised only when cua-driver is present
- The ≤1.5K-token target is NOT met with all tools on. The next lever is deferring rarely used tools behind a search op, the way `mcp` already works.
- Caveat: at this size the prefix alone sits under Anthropic's per-model minimums (1,024–4,096 tokens), so the rolling conversation breakpoint carries caching.

## 3. Tool design and efficiency

Best ideas worth stealing, not yet adopted:
- **Anchored or hashline edits** (omp): lines are addressed by content hash, and stale anchors are rejected before apply. Vendor claim: −61% output tokens [vendor].
  - Plan: prototype it behind `EditFormat`, and adopt only if the eval rig reproduces the gain.
- **Code-mode tool**: the model writes one program that calls tools, and intermediate results never enter context.
  - omp (Python/Bun kernels), Hermes (`execute_code`) and DeepSeek's `dsh` (Code mode) all converged on this [src].
  - Anthropic reports 150K → 2K tokens on MCP workloads [src].
- **Stream rules (TTSR)** (omp): a regex or AST match on the output stream aborts, injects a rule, and retries from the same point. Rules cost zero context until they fire [src]. Unique to omp.
- **Model roles with fallback chains** (omp): default, vision, web and small roles, with per-role retry chains [local config].

## 4. Computer use and browser control

**cua-driver 0.26.1** [local: tool descriptions dumped from the binary]
- One binary with three transports: `mcp` (stdio, proxied to the CuaDriver.app daemon so macOS permission prompts are attributed to it), `serve` (daemon) and `call` (one-shot).
- Background-first input: pid-targeted, with no cursor warp and no focus steal.
- `get_window_state` returns an accessibility tree (`element_index` / `element_token`) plus a screenshot, with switches to skip either half.
- Actions choose the rung at call time: accessibility element or pixel.
- `verify_state` gives deterministic post-conditions; "unknown" never counts as success.
- `zoom` crops, and `max_dimension` caps screenshot size.
- Browser tools use CDP, with semantic refs that die on navigation.
- Browser support: Chrome and Edge are supported. Safari, Firefox, Arc and others are refused with a structured error and fall back to accessibility plus pixel control [src: cua docs].
- Hermes wraps cua-driver as its `computer_use` toolset over stdio MCP [src].

**Overseer [verified]**
- The `computer` tool dispatches to helper binaries named by `OVERSEER_COMPUTER_*`. None ship, so it always errors, yet it is always advertised.

**Shipped (S5; live macOS verification still pending)**
- A cua-driver backend for the existing single `computer` tool. It talks MCP over stdio to `cua-driver mcp`, reusing `mcp.rs`'s env-allowlisted client, with a lazy spawn and a session-scoped child.
- The driver path must be absolute; relative PATH entries are ignored.
- Coordinates are passed verbatim in the driver's own frame, and zoom crops use the driver's `from_zoom`. This rule is still to be confirmed by the `#[ignore]` `computer_live` test on a Mac.
- Only the last 2 screenshots stay in the model view.
- Every driver string is sanitized before rendering.
- 19 actions plus `batch`, all behind one byte-stable spec. It is tree-first, with screenshots only on demand, spilled to files owned by the user.
- The loop is snapshot, act, `verify_state`.
- Every observation latches the Rule-of-Two "untrusted" taint.
- Browser: Chrome-family via cua-driver's CDP refs; everything else through accessibility.

Accuracy landscape (Sep 2026, mostly vendor-reported) [src]:
- OSWorld-Verified frontier: about 83–86%.
- Online-Mind2Web: browser-use claims 97% (run by the vendor).
- Token cost per page: an accessibility snapshot is about 200–400 tokens, versus 3–50K for a screenshot.

## 5. Memory: "revealing the human mind"

**Cognitive model to engineering mechanism**

| cognitive model | engineering mechanism | status |
|---|---|---|
| Atkinson–Shiffrin | event log → context window → memory dir | have |
| Baddeley's episodic buffer | the compaction recency tail | have |
| Tulving's episodic / semantic / procedural split | layers exist; add time-anchored episodes, one per session | add |
| Complementary Learning Systems | fast episodic writes, slow semantic promotion at consolidation | partial |
| Hippocampal indexing | INDEX.md as a pointer index; add cue keys for pattern completion | upgrade |
| ACT-R base-level activation, B = ln Σ t_j^−0.5 | ranking and eviction | add |
| Ebbinghaus forgetting curve | graded decay that drops a pointer from INDEX, never the file | add |
| Reconsolidation | a contradiction flags both files for the next sleep pass | add |
| Spreading activation | `[[links]]` with one-hop expansion | add |
| Prospective memory | a `prospective/` layer checked each turn by a deterministic scan | add |
| Event segmentation | session and compaction boundaries | have |

**Benchmark reality [src]**
- LongMemEval-S tops out around 95–96% on a real retrieval pipeline.
- LoCoMo vendor claims of 92–96% fall to 65–85 in independent reruns, so treat vendor numbers as marketing.
- MemoryAgentBench multi-hop conflict resolution is ≤7% for every system: the unsolved frontier.
- Memory poisoning is real: MINJA reaches about 70% attack success, AgentPoison ≥80%.

**Overseer [verified]**
- The store is git-versioned: INDEX.md plus CORE.md resident, four layers, frontmatter with provenance, confidence and validity.
- About half of `memory.rs`'s public API is dead scaffolding.
- Scoring is lexical.
- A bug means `MemoryUpdated` never fires.
- Consolidation's "ADD-only" contract is not enforced.

**Decision**
- Shipped (S2b):
  - bug fixes: `MemoryUpdated` now fires, ADD-only consolidation is enforced including layer-qualified pointers, and expiry is compared by epoch
  - the dead API is deleted
- Next, memory v2 (design only, not yet built):
  - SQLite FTS5 as a rebuildable index, no daemon.
  - Score = 0.45·BM25 + 0.25·ACT-R activation + 0.15·confidence + 0.10·link activation + 0.05·context match. The weights are provisional and get tuned on the eval.
  - A cross-project user store in `~/.overseer/memory/`.
  - A prospective layer.
  - A session-end "sleep" pass on the small model: episode summary, merges with supersession, promotion to skills.
  - Untrusted-latch writes are forced to low confidence and go through approval.
  - A resident budget of ≤2.5K tokens, kept byte-stable per session.
  - Eval: a LongMemEval-S adapter in the rig.

## 6. Subagent orchestration

**Evidence**
- Anthropic's multi-agent research system: +90% on its internal eval at about 15× the tokens [src]. It pays only for parallel, context-exceeding work.
- Cognition's rules still hold [src]: share context, and keep writes serialized so subagents stay read-only.
- Fusion-style lead plus persistent cheap sidekick exchanges briefs and results, never transcripts. Vendor claim: 35–60% lower cost [vendor].
- MAST [src]: task verification is a top failure class. A fresh-context verifier beats self-critique.

**Overseer [verified]**
- `task` already has read, write (in a worktree) and background modes, a cap of 4 in flight, and 8K-char digests.
- Missing: per-subagent model or tier, a per-subagent cost cap, resume, and a verifier profile.
- Bug: background writes lose their worktree pointer. S2a fixes it.

**Next**
- Light/medium/heavy tier routing: Factory's `subagentModelSettings` shape [local].
- A persistent sidekick mode.
- A `consult` (advisor) tool.
- A fresh-context verifier profile for write tasks.
- Per-subagent cost caps.

## 7. Architecture and lightness

- Dependencies are already lean: core has no tokio and no reqwest; it uses ureq with rustls and regex-lite. The binary is about 5.5 MB.
- Codex's 80 MB cautionary tale came from its dependencies, not from Rust [src].
- ACP is now the editor protocol: about 35 agents, including Claude Code, Codex and Droid, with Zed and JetBrains as clients [src].
- Next: a thin ACP adapter crate over overseer-proto, sync threads, no tokio.

## 8. UX, the localhost surface, packaging and brand

**Security [verified in code]**
- The web surface accepted unauthenticated `GET /input` on a fixed port with no Host check. Any web page could type into a shell-capable agent.
- Shipped:
  - a per-install token in the URL fragment, stored in localStorage
  - Host allowlist, Origin and Sec-Fetch-Site checks
  - body, connection and timeout limits
  - non-blocking SSE
  - CSP
  - port fallback and auto-open

**Packaging**
- cargo-dist is configured with `installers = []`. S3 enables shell and Homebrew installers; the artifacts appear at tagged releases.
- A PWA manifest makes localhost install like a native app window [src: MDN].

**Design**
- The "graphite" palette with contrast checked by the lead: text 11.3:1, dim 4.75:1.
- Harness activity recedes: tool lines indented, colour only for state.
- A quiet run line: `19 steps · 1m 12s · $0.042 · 87% cached`.
- The installed app window is full-bleed.
- Brand: four marks explored (cloche, bowtie, gaze, monocle). The owner chose the **bowtie in its bold cut** as the global logo; `web/mark.svg` is the single source, and the terminal glyph is `⋈`.
